# 공부 플로우

> 세 단계로 나눠 읽는 노트. 코드와 같이 보면 된다.
>
> 노션: 이 파일 전체를 복사 → 페이지에 붙여넣기.

관련 구조 요약은 `docs/kanji_kr_구조.md`.

---

## 어떻게 읽을지

| 단계 | 목표 | 시간 | 열 파일 |
|------|------|------|---------|
| 1 | 화면만 고치기 | 30분–1시간 | `study_page.dart`, `home_pickers.dart`, `quiz_page.dart` |
| 2 | 목록이 왜 나오는지 | 1–2시간 | `lists.json` → repository → `study_filter.dart` → session |
| 3 | 추가 / 즐겨찾기 | 반나절 | `UserStore` + `CatalogController` + add/list 화면 |

한 단계씩만 본다. 1에서 2의 저장 구조를 파고들지 않아도 화면은 고칠 수 있다.

공통으로 알아 둘 상태 두 개:

- `studySessionProvider` — 홈·목록 탭이 같이 보는 선택 (한자/동사, 목록 id)
- `quizSessionProvider` — 퀴즈 탭 전용. 홈 목록과 섞지 않음. 기기에 안 남김

세션 판별:

- `hasKind` = 한자 또는 동사를 골랐다
- `hasDeck` = kind + listId 둘 다 있다 → 카드/퀴즈를 연다

## 1. 화면만 고치기 (30분–1시간)

이 단계의 질문: **지금 화면에 뭐가 그려지나, 버튼을 누르면 로컬 상태만 바뀌나.**

데이터 출처는 “카탈로그가 이미 있다”고 치고 넘어간다.

### 1-1. 홈이 세 화면인 이유

파일: `lib/features/study/study_page.dart`

`StudyPage.build`가 카탈로그를 받은 뒤 분기다.

```
카탈로그 로딩 중 → 스피너
카탈로그 에러 → 에러 텍스트
그 외:
  initialId 없고 hasDeck 아님 → HomeBrowseBody  (고르기)
  hasDeck 또는 /kanji/:id     → 플래시카드
```

핵심 조건 (`study_page.dart`):

- `widget.initialId == null && !session.hasDeck` → 피커
- 그 외 → `_deck()`으로 카드 배열을 만들고 PageView

`/kanji/:id`로 들어오면 `initialId`가 있다. 목록 탭·즐겨찾기에서 타일을 눌렀을 때. 이때는 피커를 건너뛰고 그 카드로 점프한다. 뒤로가기는 `context.pop()`.

홈 탭에서 카드를 보다가 뒤로가기는 pop이 아니다. `clearList()` → 목록 고르기, 한 번 더면 `clearKind()` → 한자/동사 고르기. `PopScope`가 그걸 한다.

### 1-2. 한자/동사 → 목록 (`home_pickers.dart`)

`HomeBrowseBody`는 세션만 본다.

```
hasKind 없음 → _KindStep   (한자 / 동사 두 장)
hasKind 있음 → _ListStep   (그 종류의 목록 + 장 수)
```

한자를 누르면:

- 홈: `studySessionProvider.selectKind(kanji)` → listId를 비움 → 목록 화면
- 퀴즈: `quizSessionProvider.selectKind(...)` 만. 홈 선택은 그대로

목록 줄을 누르면 `selectList(list.id)` → `hasDeck == true` → 부모(`StudyPage` 또는 `QuizPage`)가 피커 대신 카드/퀴즈를 그린다.

`forQuiz: true`가 퀴즈 탭에서 넘어온다. 같은 UI, 다른 Provider.

직접 해볼 것:

- `_KindCard` 제목/아이콘만 바꿔 보기
- `_ListCard`에 장 수 대신 다른 문구
- 한자/동사 순서를 바꾸기

이 파일만으로 “목록에 뭐가 들어가나”는 안 보인다. 줄 목록은 `catalog.dropdownLists(...)`가 만들어 준다 → 단계 2.

### 1-3. 플래시카드 (`study_page.dart` 나머지)

레이아웃 위→아래:

1. `_StudyHeader` — 제목 가운데, 아래줄 셔플·다크 / 장수·검색
2. 좌우 화살표 + `PageView` (`_KanjiFlashCard`) — 글자만 크게, 오른쪽 위 하트
3. 높이 148 슬롯 — 정답을 열면 `_AnswerBlock`, 닫으면 빈 공간 (카드가 안 밀리게)
4. 분홍 “정답” 버튼
5. 아래 `Spacer`

정답 열기:

- 탭: 이 장 인덱스만 `_revealed`에 넣거나 뺀다 (세션 메모리, persist 없음)
- 더블탭: `studyPrefsProvider.toggleAlwaysShowAnswer()` — 전역, 기기에 남음
- `alwaysShowAnswer == true`이면 `_revealed`를 안 보고 항상 답을 보여 준다

셔플: `studySessionProvider.shuffle()` → `shuffleNonce`가 시각(ms)으로 바뀜 → `ref.listen`이 `_resetDeck()` → 첫 장부터, 같은 nonce로 섞인 순서.

검색: 현재 덱만 `showKanjiSearchSheet`로 찾고, 고른 카드 인덱스로 `_jumpTo`.

손대면 바로 보이는 곳:

- `_KanjiFlashCard` 글자 크기 (단어 72 / 한자 96)
- `_AnswerBlock` 뜻 28px, 읽기 20px, 힌트 16px
- 정답 슬롯 높이 148
- 헤더 색 `0xFFE85A7B`

아직 안 봐도 되는 것: `_deck()` 안의 `resolveListId` / `withShuffle` 구현. “목록 id로 카드를 거른 뒤 nonce로 섞는다” 정도만.

### 1-4. 퀴즈 (`quiz_page.dart`)

홈과 같은 2단 피커 (`HomeBrowseBody(forQuiz: true)`).

```
quizSession.hasDeck 없음 → 피커
있음 + 카드 2장 이상     → 다음 프레임에 _begin() (자동 시작)
있음 + 2장 미만          → “퀴즈를 만들 수 없음”
플레이 중                → 문제 + 보기
마지막 다음              → 점수 + 다시 풀기
```

로컬 상태 (`_QuizPageState`, persist 없음):

| 필드 | 의미 |
|------|------|
| `_mode` | 뜻 맞히기 / 글자 맞히기 |
| `_questions` | `buildQuiz` 결과 |
| `_index` | 지금 문항 |
| `_picked` | 고른 보기. null이면 아직 안 고름 |
| `_correctCount` | 맞은 개수 |
| `_playing` | 문항을 푸는 중. false면 시작 화면 또는 결과 |

한 문항: `_pick` → 초록/분홍 → `_next`. 마지막이면 `_playing = false` → `_ResultView`.

모드를 바꾸면 `_resetLocal()` 후 다시 `_begin`. 뒤로가기는 `_leaveQuiz()` → 로컬 리셋 + `clearList()` → 목록 고르기로.

문항 생성 자체는 `lib/features/quiz/quiz_builder.dart`. 화면만 고칠 때는 “보기는 정답 1 + 오답 최대 3”만 알면 된다.

### 1-5. 하단 바가 사라지는 이유 (참고만)

`lib/core/router/app_router.dart` `AppShell`:

- 홈: kind 고르기 전, 또는 이미 카드 → 바 숨김
- 퀴즈: 문제 푸는 중 → 바 숨김
- 목록 고르는 화면 → 바 유지 (퀴즈 탭으로 갈 수 있게)

퀴즈 탭을 처음 누르면, 퀴즈에 kind가 없을 때 홈 kind를 복사한다.

단계 1 끝: 피커/카드/퀴즈 UI를 바꿔도 데이터가 어디서 오는지는 몰라도 된다.

## 2. 목록이 왜 나오는지 (1–2시간)

이 단계의 질문: **‘초급 동사 200장’ 줄은 누가 만들고, 누르면 왜 그 카드만 나오나.**

한 줄로:

```
lists.json
  → KanjiRepository.ensureReady  (에셋 로드, 메모리 DB에 카드 넣기)
  → CatalogState.builtinLists + kanjis
  → composeListsForKind          (화면에 줄 만들기)
  → StudySession.listId
  → itemsForList                 (그 줄의 카드만)
  → StudyPage / QuizPage
```

### 2-1. `lists.json` — 목록 목차

파일: `assets/data/lists.json`

카드가 아니라 **목록 메타**다. 각 줄:

| 필드 | 역할 |
|------|------|
| `id` | 세션에 저장되는 목록 id. 예: `verb_beg` |
| `kind` | `kanji` 또는 `word`. 한자/동사 고른 뒤 필터에 씀 |
| `titleKo` | 화면에 보이는 제목 |
| `asset` | 실제 카드 JSON 경로 |

지금 6개: 한자 초/중/고급, 동사 초/중/고급.

새 목록을 앱에 넣으려면 여기 한 줄 + JSON 파일 + `pubspec.yaml` assets (이미 폴더 단위).

에셋 변경은 핫 리로드로 안 들어온다. 핫 리스타트 또는 재빌드.

### 2-2. Repository가 목차를 카드로 펼친다

파일: `lib/features/kanji_detail/kanji_detail_repository.dart`

이름은 detail이지만 **전체 카탈로그 로더**.

`CatalogController.build` → `repo.all()` → `ensureReady()`:

1. `assets/data/lists.json`을 읽는다
2. `n5_word` / `n5_kanji`는 빼 둔다 (예전 샘플)
3. 각 목록의 `asset` JSON을 읽어 `AppDatabase`에 `upsertKanji`
   - `listId`가 비어 있으면 목록 id를 넣는다
   - 목록 kind가 word면 카드 kind도 word로 맞춘다
4. 그 다음 `UserStore`의 사용자 카드·즐겨찾기를 **덮어씌운다** (시드 다음에 사용자)

같은 프로세스에서는 `_ready == true`면 다시 안 읽는다.

`AppDatabase`는 SQLite가 아니다. 켜져 있는 동안의 `Map`. 끄면 시드는 JSON에서 다시, 사용자 분만 UserStore에서.

### 2-3. 화면에 줄이 생기는 곳 — filter

파일: `lib/core/study_filter.dart`

홈·퀴즈 피커는 `catalog.dropdownLists(kind: session.kind)`를 부른다.
kind가 한자 또는 단어면 `composeListsForKind`:

```
builtin 중 kind가 같은 것
  + 가상 “내가 추가” (id = user)
  + 가상 “즐겨찾기” (id = favorites)
```

동사를 고르면 대략:

1. 초급 동사
2. 중급 동사
3. 고급 동사
4. 내가 추가
5. 즐겨찾기

장 수: `catalog.itemsFor(list.id, kind: kind).length`

### 2-4. 줄을 누르면 세션에 id만 남는다

파일: `lib/core/providers.dart` `StudySessionNotifier`

`selectList('verb_beg')`:

- 메모리: `StudySession(kind: word, listId: verb_beg)`
- 기기: `UserStore.patch(selectedListId: 'verb_beg')`  ← 홈만. 퀴즈는 persist 안 함

앱을 다시 켜면 홈은 마지막 목록으로 바로 카드를 연다. 퀴즈는 처음부터.

`selectKind`는 listId를 빈 문자열로 지운다. 그래서 한자→동사로 바꾸면 다시 목록을 고른다.

### 2-5. listId → 실제 카드

같은 `study_filter.dart`의 `itemsForList`:

| listId | 남는 카드 |
|--------|-----------|
| `favorites` | `favoriteIds`에 있는 것 |
| `user` | `isUserAdded == true` |
| `verb_beg` 등 | `item.listId == 'verb_beg'` |
| 빈 문자열 / `all` | 홈에서는 카드 없음 (`resolveListId`가 빈 값) |

그 다음 `kind`로 한 번 더 거른다. 동사 화면의 “즐겨찾기”는 단어만.

`resolveListId`: 저장된 id가 드롭다운에 없으면 빈 값 → 피커로 돌아간다. 목록을 지웠을 때 빈 카드를 안 보여 주려고.

학습 덱은 `_deck()`:

```
itemsFor(listId, kind)
  → withShuffle(..., shuffleNonce)
```

`shuffleNonce == 0`이면 JSON 순서 그대로.

### 2-6. 손으로 따라가기 (동사 → 초급 동사)

1. 홈에서 동사 탭
2. `_KindStep` → `selectKind(word)` → persist `selectedKind=word`
3. `_ListStep` → `composeListsForKind(word)` → 초급/중급/고급 동사 + 내가 추가 + 즐겨찾기
4. 초급 동사 → `selectList('verb_beg')`
5. `StudyPage`가 `hasDeck`을 보고 피커 대신 카드
6. `_deck` → `listId==verb_beg` 이고 `kind==word`인 카드 200장
7. PageView가 `literal`을 크게 그림

퀴즈도 4번까지 같고, 5번이 `QuizPage._begin` → `buildQuiz(items)`.

직접 해볼 것:

- `lists.json`에서 고급 동사 한 줄을 지우고 핫 리스타트 → 줄이 사라지는지
- `composeListsForKind`에서 즐겨찾기 줄을 빼 보기
- 시드 카드의 `listId`를 일부러 비우면, repository가 목록 id를 채워 주는지 (`ensureReady`의 `copyWith`)

단계 2 끝: 목차 JSON → 메모리 카드 → 화면 줄 → 세션 id → 필터.

## 3. 추가 / 즐겨찾기 (반나절)

이 단계의 질문: **시드는 안 고치고, 내 것만 기기에 어떻게 남나.**

한 줄: **에셋은 읽기 전용. 하트·추가·수정만 `UserStore` JSON.**

키: `kanji_kr_user_v1` (`lib/core/storage/user_store.dart`)

웹은 origin(포트)마다 localStorage가 갈린다. iOS/Android는 앱 지원 폴더의 `kanji_kr_user.json`.

### 3-1. 기기에 남는 필드 (`UserData`)

| 필드 | 쓰는 곳 |
|------|---------|
| `favoriteIds` | 하트 |
| `userKanjis` | 직접 추가 + 시드 수정본 |
| `selectedKind` / `selectedListId` | 홈 마지막 선택 |
| `alwaysShowAnswer` / `isDark` | 정답 항상 표시, 다크 |

시드 원문은 여기 없다. 켤 때마다 에셋에서 다시 읽고, `userKanjis`로 같은 id를 upsert해서 수정분을 덮는다.

### 3-2. 쓰기 파이프라인 (공통)

화면은 Repository를 직접 안 부른다.

```
UI
  → CatalogController.toggleFavorite / addUserKanji / updateKanji / deleteUserKanji
    → KanjiRepository (메모리 DB 변경 + _persist)
      → UserStore.patch(...)
    → CatalogController._reload()   // 화면 스냅샷 갱신
```

`_persist`가 저장하는 카드:

- `isUserAdded == true` 이거나
- `_persistedIds`에 있는 id (시드를 수정한 것)

시드 원본 900+600장은 저장하지 않는다.

### 3-3. 즐겨찾기

하트는 세 군데: 학습 카드, 목록 타일, 즐겨찾기 탭.

동작은 같다. `toggleFavorite(id)`:

1. `AppDatabase`의 Set에서 id를 넣거나 뺀다
2. `_persist` → `favoriteIds`만 JSON에
3. `_reload` → `CatalogState.favoriteIds` 갱신
4. 아이콘이 찬 하트/빈 하트로

카드 본문은 안 복제한다. id만 모은다.

즐겨찾기 목록 줄 (`id = favorites`)은 가상이다. `itemsForList`가 `favoriteIds`로 거른다. 동사 화면이면 단어만.

즐겨찾기 탭 (`favorites_page.dart`)은 kind와 상관 없이 `catalog.favorites` 전체. 타일 → `/kanji/:id`.

### 3-4. 직접 추가 / 수정 / 삭제

화면: `lib/features/kanji_add/kanji_add_page.dart`

- `/add` — 새 카드. 홈이 동사면 단어 폼으로 시작
- `/edit/:id` — 기존. 시드도 수정 가능. 휴지통은 `isUserAdded`만

저장:

1. 글자·뜻 검증
2. 새 카드 id = `user_` + 글자, 또는 단어면 `user_word_` + 글자
3. `listId = user`, `isUserAdded = true`, `jlpt = USER`
4. `addUserKanji` 또는 `updateKanji`
5. 같은 글자가 이미 있으면 `'alreadyExists'` → 스낵바

시드를 수정하면 그 id가 `_persistedIds`에 들어가서, 다음 실행 때 시드 위에 덮인다. 삭제는 안 된다 (repository가 `isUserAdded`가 아니면 return).

목록의 “내가 추가”는 `isUserAdded`인 카드.

### 3-5. 켤 때 합치는 순서 (다시)

`ensureReady`:

```
1. 에셋 시드 → DB
2. userKanjis upsert → 같은 id면 수정본이 이김
3. favoriteIds 적용
```

순서를 바꾸면 시드가 내 수정을 덮어 버린다. 주석에 그렇게 적혀 있다.

### 3-6. 직접 해볼 것

- 하트 후 앱 재시작 → 즐겨찾기 유지
- `/add`로 단어 하나 → “내가 추가” 장 수 +1, JSON에 `userKanjis` 생기는지
- 시드 한자 뜻만 고치기 → 재시작 후 유지, 휴지통은 없는지
- 웹에서 포트만 바꿔 실행 → 데이터가 비는 것처럼 보이는지 (localStorage origin)

## 세 단계가 만나는 지점

```
[에셋 lists.json + kanji/*.json + word/*.json]
        │ 켤 때 한 번
        ▼
 KanjiRepository + AppDatabase (메모리)
        │ 사용자 JSON upsert
        ▼
 CatalogState  (화면이 watch하는 스냅샷)
        │
        ├─ dropdownLists / itemsFor     ← 단계 2
        │
        ├─ StudyPage / HomeBrowseBody   ← 단계 1 홈
        ├─ QuizPage                     ← 단계 1 퀴즈
        │
        └─ CatalogController 쓰기       ← 단계 3
              └─ UserStore persist
```

화면만 고칠 때 만지는 곳: 단계 1 파일, 가끔 `app_theme.dart` 색.

목록이 비거나 장 수가 이상하면: 단계 2 (`lists.json`, `listId`, `kind`, `_ready` 캐시).

하트/추가가 재시작 후 사라지면: 단계 3 (웹 포트, `_persist` 조건, 시드 삭제 시도).
